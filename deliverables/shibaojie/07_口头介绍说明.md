# 口头介绍说明

## 3 分钟版本

这次交付的不是一个平台脚本，而是一套单店门店监测系统。它分两层：底层可以继续用 OpenClaw 做登录、抓取和执行；上层是我们现在交付的结果层，负责统一字段、门店规则判断、噪音过滤、去重、看板和客户说明。

如果一句话说老板视角，这套东西本质上是“傻瓜式的门店舆情 / 内容 KPI 监控”。老板不用研究部署，不用看 GitHub，也不用自己盯后台，主要就是看飞书里每个门店当天内容有没有达标。

客户之前最不满意的是 OpenClaw 太粗，像 A/B/C 三类内容里只想看 C，结果 A 和 B 也会被推过来。我们这次重点把这个问题拆开解决了：不是只靠关键词，而是同时看门店名、别名、商圈、城市、POI、探店上下文、排除词，再叠加作者级别、认证信息、粉丝量、账号标签和重点达人名单，所以“只要 C，不要 A/B”的能力会比之前稳定很多。

现在系统已经支持小红书、抖音、视频号的公开探店内容统一进门店级判断链路。命中后不仅会给标题和链接，还会给作者、认证、粉丝量、账号标签、KOL 判定、命中原因，以及一层“发布后经营波动观察”，帮助判断有没有疑似引流。

这里要讲准确一点：当前版本能做的是“内容精筛 + 疑似引流观察”，还不是精确归因到某一条视频带来多少单。真要做到精确归因，还要再接专属券码、专属链接或活动级转化链路。

## 客户追问时怎么答

### 1. 这个和之前 OpenClaw 有什么区别？

OpenClaw 还是可以继续用，但它只负责采集和执行。之前的问题是采集结果太粗，客户看到的就是原始抓取。现在客户看到的是我们精筛后的结果层，看板、报告、交付页和使用说明都已经固定下来。

### 2. 能不能盯固定达人？

可以。现在已经支持重点达人名单、认证类型、粉丝量门槛、账号标签和 POI 约束。合作达人、探店达人、本地生活号都可以单独定向监控。

### 3. 能不能实时看引流？

当前是按小时更新的准实时监控。能及时发现内容，也能结合发文后的曝光、成交、有效单做波动观察，但不能直接谎称“这条视频精确带来多少单”。

### 4. 客户平时怎么用？

客户只需要看交付文件，不需要去操作底层脚本。执行同学一键运行，客户看 `01/02/03/04` 这几份文件就够了。

如果客户后面坚持要自己跑，也不是从 PR 开始。最简单的是给完整运行包，然后按“安装 -> 打开设置 -> 验收”三个固定入口走。

### 5. 你们自己怎么验收这套东西跑通了？

最简单就是一条命令验收，不需要研究脚本细节。

先把飞书 webhook 配好，然后跑：

`./scripts/run_acceptance_demo.sh data/client_profiles/shibaojie --require-feishu`

这条命令会自动做三件事：

1. 先检查文件和配置齐不齐。
2. 先发一条飞书测试消息。
3. 再跑整店链路并生成交付文件。

验收的时候只要看三件事：

1. 飞书有没有收到消息。
2. 看板和报告有没有生成。
3. 每个门店当天内容和 KPI 状态能不能看清楚。

如果对方完全不懂命令行，我们也准备了双击运行的 `.command` 入口，实际还是跑同一条验收链路。

如果对方希望“远程装机”，更稳的方式不是我们直接接管电脑，而是让对方共享屏幕，我们按固定入口一步一步带着点。对首轮验收来说，这已经够了。

### 6. 我们自己还要不要重新登录平台？

不是每次都要。

只有三种情况才需要我们重新登录：

1. 平台登录态失效了。
2. 要补抓新的真实平台数据。
3. 平台页面字段变了，需要重新核对采集链路。

如果只是改规则、改飞书推送、改 KPI 目标值、重新导出交付页，都不需要重新登录。
