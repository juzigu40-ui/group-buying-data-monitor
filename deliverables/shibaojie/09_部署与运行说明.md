# 部署与运行说明

## 目录和角色

- 客户看结果：直接看 `01` 到 `04`
- 执行同学跑系统：主要用 `scripts/run_profile.sh`
- OpenClaw 如果保留：负责登录、抓取、调度和把原始内容写入标准输入文件
- 如果客户没有技术同学：优先用托管代跑版，不建议让门店自己从零搭环境
- 如果客户要的是门店KPI监管：优先按门店来源直连模式落地，不要只靠品牌词粗筛

## 非技术客户不要从 PR 开始

- PR 是源码和交付记录，不是非技术客户的主入口
- 非技术客户应该先拿完整运行包
- 如果开不了远程，优先让客户按固定顺序双击：
  1. Windows 直接双击 `双击这里启动系统（Windows）.bat`
  2. 它会自动安装并打开控制台
  3. 在控制台里点“测试飞书”和“运行验收”
- 这样做的目的，是让客户不需要先理解 GitHub、虚拟环境和命令行

## 控制台入口

现在运行包已经补了本地控制台入口：

- Mac: `scripts/open_control_center.command`
- Windows: `双击这里启动系统（Windows）.bat`

控制台里可以直接做：

1. 改飞书 webhook
2. 改时间段和频率
3. 改门店平台绑定
4. 改门店 KPI 目标
4. 一键安装环境
5. 测试飞书
6. 运行验收

当前第一版按“登录后后台可见数据 + 标准化输入数据”运行，不要求现在就把所有平台都切到 API。

对于没有 API 的平台，第一版默认走：

1. 账号密码 / 人工协作登录
2. 固定一台部署电脑
3. 尽量复用这台电脑本地保存的登录态 / cookie
4. 定时进入后台页面提取可见数据
5. 平台强制失效时，再补一次验证码

所以目标不是“每次都重新验证码登录”，而是“先把部署电脑上的登录态稳定下来，后面定时复用”。客户不需要自己去找本地会话文件，只看控制台里的登录状态即可。

## 如果要做门店KPI监管，规则要这样收紧

1. `store_signal_rules.json` 里给每个门店写 `daily_target_count`
2. 如果内容来自门店碰一碰 / 内容库，建议打开 `require_source_store`
3. OpenClaw 导出时要带 `source_store_id`、`source_store_name`、`source_channel`、`campaign_name`、`content_library_tag`
4. 这样飞书里看到的就不是泛舆情，而是“每个门店今天完成了多少条、还差多少条”

如果客户自己不会改门店规则，最稳的方式仍然是由我们代配，老板日常只改时间段和看飞书结果。

## 正式增量监控怎么跑

```bash
cd /Users/wolaoposongwodediannao/Downloads/codex\ ai工作文件/group-buying-data-monitor
PYTHONPATH=src python3 -m gb_monitor.cli profile-signals \
  --profile-dir data/client_profiles/shibaojie \
  --mode all \
  --notify \
  --mark-dispatched \
  --attribution-window-hours 2 \
  --board-output data/client_profiles/shibaojie/signal_watchboard.md \
  --report-output data/client_profiles/shibaojie/signal_report.txt
```

说明：

- `--mark-dispatched` 会更新去重账本，适合正式运行
- `--notify` 会把本次新增命中内容直接推到飞书
- `--attribution-window-hours 2` 表示发文后先观察 2 小时经营波动

## 如果客户继续沿用 OpenClaw

推荐配合方式：

1. OpenClaw 登录目标平台并抓取原始内容
2. 把内容落进 `signal_inputs/public_xiaohongshu.json`、`public_douyin.json`、`public_shipinhao.json`
3. 如果内容来自门店碰一碰、内容库或活动台账，最好同时补 `source_store_id`、`source_store_name`、`source_channel`、`campaign_name`、`content_library_tag`
4. 由本系统做门店规则判断、噪音过滤、达人识别、门店达标统计和看板生成
5. 客户只看最终交付文件，不看原始抓取结果

## 什么时候需要重新登录平台

- 不需要重新登录：改规则、改每日目标、改飞书推送、改看板口径
- 需要重新登录：补抓新的真实平台数据、登录态失效、平台页面字段变化

## 需要维护的关键文件

- `data/client_profiles/shibaojie/store_signal_rules.json`
  - 管门店规则、重点达人名单、粉丝量门槛、POI 约束、门店来源直连要求、每日目标值
- `data/client_profiles/shibaojie/signal_inputs/*.json`
  - 管舆情原始输入
- `data/client_profiles/shibaojie/snapshots/*.json`
  - 管经营数据快照

## 常见调整

- 要盯固定达人：改 `focus_author_names`
- 要只看认证达人：改 `focus_verified_labels`
- 要只看一定粉丝量以上账号：改 `min_follower_count`
- 要强制内容带门店 POI：改 `require_poi`
- 要严格只看门店自己引导出来的内容：改 `require_source_store`
- 要看门店当天有没有完成发帖任务：改 `daily_target_count`
- 要减少重复提醒：保持正式运行时带 `--mark-dispatched`

## 出问题先看什么

- 先跑 `profile-readiness`：确认不是缺文件或缺 webhook
- 看 `execution_board.md`：确认平台登录和链路状态
- 看 `signal_watchboard.md`：确认有没有命中和为什么被过滤
- 看 `signal_report.txt`：确认运营文本是否可直接发送
- 看 `store_signal_rules.json`：确认规则有没有写得过松或过严
- 如果配置了 webhook 但飞书没收到，先重新跑 `PYTHONPATH=src python3 -m gb_monitor.cli feishu-ping`
