# 凤状元·江西小炒·非遗米粉(食宝街店) 实时舆情交付页

- 城市：北京
- 监测时段：每天 10:00-21:00 每小时一次
- 当前目标：把小红书 / 抖音 / 视频号的公开内容统一进入门店级判断和飞书派发链路。
- 当前规则数：3
- 当前候选内容数：6
- 当前已识别输入文件：public_xiaohongshu.json, public_douyin.json, public_shipinhao.json

## 这套系统如何真正解决实时舆情问题

1. 不是模糊的“OpenClaw+skills”，而是固定输入文件 + 门店规则 + 调度窗口 + 去重账本 + 派发输出。
2. 输入层先把各平台内容转成统一 JSON，确保作者、链接、时间、互动量、POI 等字段能被稳定读取。
3. 规则层按门店名、商圈、城市、POI、上下文和排除词同时判断，不靠单个关键词碰运气。
4. 判断层会输出命中词、命中字段、作者/IP、认证信息、粉丝量、账号标签、KOL 判定和原因，客户能看到为什么推送、为什么过滤。
5. 去重层会记录已发内容，同一条内容不会在短时间内反复轰炸飞书。
6. 对有发布时间的内容，系统会补一层“发布后经营波动观察”，用于辅助判断疑似引流，不冒充精确归因。
7. 派发层可直接生成 `signal_report.txt` 和 `signal_watchboard.md`，配置飞书 webhook 后也可以自动推送到飞书。

## 当前规则覆盖方式

- 每个平台都有独立门店规则，最低命中分默认不低于 8 分。
- 规则同时包含门店名、别名、城市、位置上下文、餐饮上下文和排除词。
- 规则还支持按重点达人名单、作者级别、认证信息、粉丝量、账号标签和是否带 POI 做更严格的达人监控。
- 重点达人常用配置字段包括：`focus_author_names`、`focus_author_tags`、`focus_verified_labels`、`author_level_include_keywords`、`min_follower_count`、`require_poi`。
- 对凤状元这类容易撞到戏曲/民俗内容的词，已经单独加了噪音排除规则。

## 关于“网红达人带来多少引流”

- 当前版本能做的是：内容精筛 + 发布后经营波动观察。
- 系统会在内容发布时间后的观察窗里，对抖音曝光、抖音成交额、抖音成单量、美团/闪购/京东有效单做波动比对。
- 这能帮助判断“疑似引流贡献”，但不会谎称已经做到精确到单条视频的硬归因。
- 如果后面要做到精确归因，需要再接达人专属券码、专属链接或活动级转化链路。
- 如果客户有固定合作达人，可以直接把达人昵称、认证类型、账号标签写进重点名单，系统会单独加权监控。

## 本次交付会一起给客户什么

- `signal_inputs/README.md`：说明输入格式、字段要求和最小示例。
- `signal_watchboard.md`：面向运营或老板的舆情看板。
- `signal_report.txt`：适合飞书直接发送的文本版命中结果。
- `signal_delivery_explainer.md`：说明这套系统怎么解决“实时舆情太模糊”的问题。
- `client_usage_guide.md`：告诉客户日常怎么用，以及如果继续用 OpenClaw 应该怎么接。
- `store_signal_rules.json`：执行同学可继续往里加重点达人名单、粉丝量门槛和 POI 约束。

## 对客户的说明口径

这套实时舆情不是一句“会用 OpenClaw+skills 做监测”的抽象表述，而是已经明确到输入、规则、时间窗、过滤逻辑和派发结果的系统。OpenClaw 如果继续用，也只承担采集和执行层，不直接作为客户看到的交付结果。后面即使再补小红书或视频号的真实来源，也只是往标准输入文件里加数据，不需要推倒重来。
