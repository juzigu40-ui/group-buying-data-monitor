# 客户运行包先看这里

## 先说最重要的

这个运行包不是让老板自己研究代码和 PR。

如果你们只是验收这套系统有没有跑通，最简单的方式是：

1. 先安装。
2. 再打开控制台。
3. 在控制台里填飞书、时间段、门店平台绑定和门店目标。
4. 点“测试飞书”。
5. 点“运行验收”。
6. 看飞书有没有收到消息和结果文件有没有生成。

## 先看哪几份文件

建议按这个顺序看：

1. `01_单店交付页.md`
2. `02_实时舆情交付说明.md`
3. `04_系统使用说明.md`
4. `12_零技术门店KPI监管接入清单.md`
5. `13_一条命令验收跑通说明.md`

## 如果你们没有技术同学

最推荐的方式不是自己搭环境，而是我们托管代跑。

你们只需要：

1. 给飞书 webhook。
2. 给每个门店的目标值。
3. 看飞书里的结果。

## 如果你们确实要自己跑

最简单的方式不是手敲命令，而是双击运行根目录这两个文件：

```bash
./1_先双击安装.command
```

然后双击：

```bash
./2_再双击打开控制台.command
```

如果是 Windows，就双击：

```text
1_先双击安装.bat
2_再双击打开控制台.bat
```

控制台里会直接给你：

1. 飞书配置
2. 时间段和频率配置
3. 门店平台绑定配置
4. 门店 KPI 目标配置
5. 测试飞书按钮
6. 运行验收按钮

频率这块已经做成可直接填写：

- `30` = 每 30 分钟
- `60` = 每 1 小时
- `10` = 高峰期更密的抓取频率

当前第一版先跑“登录后后台可见数据 + 标准化输入数据”，不是所有平台都已经切成官方 API。

登录这块的默认思路也不是“每次都重新输验证码”，而是：

1. 先在受控电脑上完成一次登录
2. 优先保存登录态 / cookie
3. 后续定时抓取尽量复用本地登录态
4. 只有在平台强制失效、改版或触发风控时，再补一次验证码

如果你们有人会命令行，也可以在运行包根目录执行：

```bash
./scripts/install_local.sh
```

这条安装命令会自动做：

1. 创建 `.venv`
2. 安装项目
3. 生成 `.env`

然后把 `.env` 里的 `GBM_FEISHU_WEBHOOK` 填好，再执行：

```bash
./scripts/run_acceptance_demo.sh data/client_profiles/shibaojie --require-feishu
```

## 你们验收时只需要看 3 件事

1. 飞书有没有收到测试消息和正式结果。
2. 是否生成了结果文件。
3. 看板里能不能看到每个门店当天内容和 KPI 状态。

## 如果你们开不了远程

也可以继续推进，不会卡在“必须远程安装”这一步。

最简单的替代方式是：

1. 你们只按固定顺序双击根目录安装脚本和控制台入口。
2. 如果中间报错，把页面截图发回来。
3. 我们按截图告诉你下一步点哪里、改哪里。
