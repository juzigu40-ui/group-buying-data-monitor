# 凤状元·江西小炒·非遗米粉(食宝街店) 系统使用说明

- 城市：北京
- 适用对象：门店老板 / 运营 / 代运营 / 内部执行同学
- 核心原则：客户看到的是稳定的门店监测系统，不是直接操作底层采集脚本。

## 客户怎么理解这套系统

1. OpenClaw 可以继续保留，但它的角色是采集和执行引擎，不是最终交付本身。
2. 客户真正使用的是标准化后的结果层：门店指标快照、执行面板、舆情看板、舆情报告。
3. 这样做的好处是：以后即使换采集方式，客户使用方式也不用改。
4. 如果客户关心每个门店当天发了多少相关内容，系统现在已经支持按门店统计内容数量和达标状态。
5. 如果客户关心达人视频带来的引流，当前版本会给出“发布后经营波动观察”，但不会冒充精确归因。

## 如果客户完全不懂怎么搭

1. 推荐直接按托管代跑版交付：我们负责跑系统，结果直接推飞书，客户不用自己搭环境。
2. 客户最少只需要提供飞书群机器人 webhook，以及门店考核目标值，不需要自己去研究脚本。
3. 只有在补抓真实平台数据、采集入口变更或平台登录失效时，才需要重新登录平台；平时改规则、改看板、改飞书推送都不需要重新登录。

## 最简单的验收跑法

如果要给客户演示“整套系统已经跑通”，最简单就是跑这一条：

`./scripts/run_acceptance_demo.sh data/client_profiles/shibaojie --require-feishu`

这条命令会自动做 3 件事：

1. 先做自检，看 profile、规则、飞书 webhook 齐不齐。
2. 先打一条飞书测试消息。
3. 再跑整店链路并生成交付文件。

客户真正要看的不是命令细节，而是：

1. 飞书有没有收到消息。
2. `single_store_deliverable.md`、`signal_watchboard.md`、`signal_report.txt` 有没有生成。
3. 看板里能不能看到门店当天内容和 KPI 状态。

## 客户日常使用顺序

1. 先看 `single_store_deliverable.md`，确认门店当前整体交付状态。
2. 再看 `execution_board.md`，确认哪个平台已打通、哪个平台还在补。
3. 看 `signal_watchboard.md` 和 `signal_report.txt`，确认各门店当天命中了多少条内容、有没有达标。
4. 需要查经营指标时，直接看最新导出的交付页或查询最新指标结果。

## 运行模式怎么选

1. 托管代跑版：推荐给没有技术同学的客户。我们把链路跑在现有环境里，结果直接推飞书，客户只看飞书和交付页。
2. 客户自跑版：适合客户至少有人会开终端命令。先做自检，再验通飞书，再跑整店链路。
3. 如果客户完全没有技术人员，建议先按托管代跑版交付，不要硬让门店自己搭环境。

## 如果你们的目标是门店KPI监管

1. `store_signal_rules.json` 里给每个门店写 `daily_target_count`，表示当天至少要完成多少条内容。
2. 如果这批内容本来就是从门店碰一碰 / 内容库发出去的，就把 `require_source_store` 打开，只统计门店来源直连内容。
3. OpenClaw 或其他采集导出至少要写进 `source_store_id`、`source_store_name`、`source_channel`、`campaign_name`、`content_library_tag`。
4. 飞书里重点看三个值：今日相关内容、门店直连记账、距离目标还差多少条。

## 如果客户还是希望继续用 OpenClaw

可以，但要把职责说清楚：
- OpenClaw：负责登录、抓取、调度、把原始内容写进标准输入文件。
- 本系统：负责统一字段、门店规则判断、噪音过滤、去重、落库、出看板、出飞书文本。
- 客户最终看的是本系统产出的交付文件，而不是原始抓取结果。
- 如果能从碰一碰、内容库或活动台账里拿到门店来源字段，就把 `source_store_id` / `source_store_name` 一起写进标准输入，门店归属会比纯文本精筛更稳。
- 如果要专盯重点达人，可以继续在规则里加作者级别、认证信息、粉丝量和 POI 门槛。

## 执行同学怎么跑

1. 先在 `.env` 里补 `GBM_FEISHU_WEBHOOK`；如果要飞书里 @ 人，再补 `GBM_FEISHU_AT_MOBILES`。
2. 先做运行前自检：`PYTHONPATH=src python3 -m gb_monitor.cli profile-readiness --profile-dir 'data/client_profiles/shibaojie' --require-feishu`。
3. 再测试飞书机器人连通性：`PYTHONPATH=src python3 -m gb_monitor.cli feishu-ping`。
4. 跑整店链路：`./scripts/run_profile.sh data/client_profiles/shibaojie`。如果 `.env` 已配置 webhook，这条命令会自动把运行摘要和实时舆情结果推到飞书。
5. 只跑实时舆情正式增量：`PYTHONPATH=src python3 -m gb_monitor.cli profile-signals --profile-dir 'data/client_profiles/shibaojie' --mode all --notify --mark-dispatched --attribution-window-hours 2 --board-output 'data/client_profiles/shibaojie/signal_watchboard.md' --report-output 'data/client_profiles/shibaojie/signal_report.txt'`
6. 导出客户展示版完整快照：`PYTHONPATH=src python3 -m gb_monitor.cli profile-signals --profile-dir 'data/client_profiles/shibaojie' --mode all --dedupe-hours 0 --attribution-window-hours 2 --board-output 'data/client_profiles/shibaojie/signal_watchboard.md' --report-output 'data/client_profiles/shibaojie/signal_report.txt'`
7. 生成舆情说明页：`PYTHONPATH=src python3 -m gb_monitor.cli profile-signal-deliverable --profile-dir 'data/client_profiles/shibaojie' --output 'data/client_profiles/shibaojie/signal_delivery_explainer.md'`
8. 生成客户使用说明：`PYTHONPATH=src python3 -m gb_monitor.cli profile-usage-guide --profile-dir 'data/client_profiles/shibaojie' --output 'data/client_profiles/shibaojie/client_usage_guide.md'`

## 重点达人怎么配置

- 打开 `data/client_profiles/shibaojie/store_signal_rules.json`。
- 常用字段：`focus_author_names`、`focus_author_tags`、`focus_verified_labels`、`author_level_include_keywords`、`min_follower_count`、`require_poi`、`require_source_store`、`daily_target_count`、`store_aliases`。
- 推荐做法：合作达人放进重点名单；泛探店号用认证/粉丝量/POI 做门槛；招商加盟号继续放排除词。
- 如果客户要按门店每日达标数做考核，就给对应门店写 `daily_target_count`。
- 如果客户要严格只看门店自己引导出来的内容，就把 `require_source_store` 打开，并让 OpenClaw 写入 `source_store_id` / `source_store_name`。
- 给客户导出完整展示版时，不带 `--mark-dispatched`，并把 `--dedupe-hours` 设为 `0`。

## 需要客户补什么

- 登录验证码或二次验证时，按执行面板顺序一次性配合。
- 如果要接更多舆情来源，只需要继续补标准输入文件，不需要改客户使用方式。
- 如果要提高门店归属准确度，最好补 `source_store_id`、`source_store_name`、`source_channel`、`campaign_name`、`content_library_tag` 这些字段。
- 如果要自动飞书推送，只需要补 webhook，不需要重做规则。
- 如果客户自己要跑，至少要拿到仓库代码、本地 profile 目录、Python 环境和飞书机器人 webhook。
