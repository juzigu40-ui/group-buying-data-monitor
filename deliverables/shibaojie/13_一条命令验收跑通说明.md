# 一条命令验收跑通说明

## 先说最简单的话

这套系统不是让老板自己研究脚本。

最简单的验收方式就是：

1. 把飞书机器人 webhook 配好。
2. 跑一条验收命令。
3. 看飞书有没有收到消息。
4. 看 5 份结果文件有没有生成。

如果这 4 步都成立，就说明整套链路已经跑通。

## 验收命令

```bash
cd /Users/wolaoposongwodediannao/Downloads/codex\ ai工作文件/group-buying-data-monitor
./scripts/run_acceptance_demo.sh data/client_profiles/shibaojie --require-feishu
```

## 这条命令会自动做什么

1. 先检查 profile 文件齐不齐。
2. 检查飞书 webhook 有没有配置。
3. 先发一条飞书测试消息。
4. 再跑整店链路。
5. 自动生成交付文件。
6. 如果缺文件、缺 webhook、链路失败，命令会直接报错停下。

## 跑完以后看什么

### 飞书

至少要看到两类结果：

1. 飞书测试消息。
2. 正式运行摘要 / 实时舆情结果。

### 本地文件

至少要生成这 5 份：

1. `single_store_deliverable.md`
2. `signal_watchboard.md`
3. `signal_report.txt`
4. `signal_delivery_explainer.md`
5. `client_usage_guide.md`

## 什么时候我们自己需要重新登录平台

不需要重新登录：

1. 改规则。
2. 改门店每日目标值。
3. 改飞书推送。
4. 改看板和交付页。

需要重新登录：

1. 平台登录态失效了。
2. 要重新补抓真实平台数据。
3. 平台页面字段变了，需要重新核对采集链路。

## 这次客户真正要验的是什么

不是验“我们会不会写脚本”。

而是验这 3 件事：

1. 能不能按门店统计当天相关内容。
2. 能不能把结果推到飞书。
3. 能不能看出每个门店离 KPI 还差多少条。
