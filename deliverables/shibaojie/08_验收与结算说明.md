# 验收与结算说明

## 当前公开写明的口径

截至 2026-03-07，公开仓库主页 `README.md` 里明确写出来的只有这些：

- 悬赏金额：`¥3,000 RMB`
- 交付物：`完整 Skill 源码 + 部署文档 + 使用说明`
- 验收方式：`PR 合并后 3 个工作日内支付`

这意味着现在可以公开、稳妥对外引用的付款口径，只有“PR 合并后 3 个工作日内支付”这一条。

## 当前没有写清楚的地方

公开说明里没有明确写这些细节：

- 谁是最终验收确认人
- 验收到底以“代码合并”为准，还是以“客户实际跑通”为准
- 是否包含合并后的修改轮次
- 支付方式是微信、支付宝、对公还是其他方式
- 是否需要开票 / 税务怎么处理
- 部署协助和后续答疑是否算在赏金里

## 交付时建议的稳妥说法

可以这样说：

“目前公开写明的结算口径是 PR 合并后 3 个工作日内支付。为了避免后续理解偏差，建议在最终交付前把付款方式、验收确认人、是否包含一轮交付后修正，以及是否需要开票这几个点补确认一下。”

## 建议发出的确认消息

你好，这边在正式交付前，把验收和结算口径跟你确认一下，避免后面理解偏差：

1. 当前公开写明的是 PR 合并后 3 个工作日内支付，这个口径我们按这个执行，对吗？
2. 最终验收确认人是谁？是仓库 maintainer，还是你们业务侧指定同学？
3. 合并后如果还有一轮小修正，是否默认包含在本次赏金范围内？
4. 付款方式是微信 / 支付宝 / 对公，还是你们有固定流程？
5. 如果需要开票，税务口径怎么处理？

这几个点确认后，我们这边就按最终版本完整交付。
